---
title: Server-side sends
description: Drive Whisk from a backend with your own signing key, no React or user signature.
---

`<WhiskSend>` is built for a connected user wallet. Most integrations
look like that — the visitor opens your page, clicks **Send**, and
their wallet pops a signature prompt. But not every USDC payment is
user-initiated. Treasury moves, scheduled disbursements, batch
payouts, marketplace settlement, employee payroll — these are flows
where _your backend_ needs to send USDC on a schedule or in response
to a server event. No browser, no user signature.

Whisk supports this path natively because the engine and the React
layer are decoupled. Import `@usewhisk/core` on the server, build an
adapter around your own signing key (viem for EVM, `starknet.js` for
Starknet, etc.), and call the same `send()` / `refund()` methods the
widget calls.

## When this is the right tool

| Scenario                                              | Server-side | Widget (user wallet) |
| ----------------------------------------------------- | ----------- | -------------------- |
| Customer pays you for an order                        |             | ✅                   |
| Donor sends to your treasury                          |             | ✅                   |
| You pay out 200 contractors at end of month           | ✅          |                      |
| Scheduled stablecoin disbursement (DAO grant, salary) | ✅          |                      |
| Marketplace splits settlement to sellers              | ✅          |                      |
| Internal treasury rebalancing across chains           | ✅          |                      |

If a _user_ needs to sign, the widget is right. If _your service_
needs to sign on behalf of a wallet you control, this page.

## The pieces you need

1. **A signing key.** For EVM: a private key funded with USDC on
   the source chain. For Solana / Stellar / Starknet: the equivalent
   secret material in that ecosystem's format.
2. **`@usewhisk/core`** (the engine) and **`@usewhisk/cctp`** (the
   protocol layer). No React. Both are pure TypeScript.
3. **viem** (or your ecosystem's equivalent SDK) for the actual
   transaction signing and receipt polling.

## Wire it up (EVM)

Three steps: build the adapter, build the engine, send. Whisk's
adapter interface is small — implement `sendCalls`, `waitForReceipt`,
`getChainId`, `switchChain` around your signer.

```ts title="server/adapter.ts"
import { createPublicClient, createWalletClient, http, type Hex } from "viem";
import { privateKeyToAccount, nonceManager } from "viem/accounts";
import { baseSepolia } from "viem/chains";
import type { EvmAdapter, EvmCall } from "@usewhisk/core";

export function createEvmAdapter(privateKey: Hex): EvmAdapter {
  const account = privateKeyToAccount(privateKey, { nonceManager });
  const transport = http();
  const publicClient = createPublicClient({ chain: baseSepolia, transport });
  const walletClient = createWalletClient({
    account,
    chain: baseSepolia,
    transport,
  });

  return {
    kind: "evm",
    address: account.address,

    async getChainId() {
      return baseSepolia.id;
    },
    async switchChain(id) {
      if (id !== baseSepolia.id) {
        throw new Error(`Adapter pinned to ${baseSepolia.id}, got ${id}`);
      }
    },
    async sendCalls(calls: EvmCall[]) {
      const hashes: `0x${string}`[] = [];
      for (const call of calls) {
        const hash = await walletClient.sendTransaction({
          to: call.to,
          data: call.data,
          value: call.value,
          account,
          chain: baseSepolia,
        });
        hashes.push(hash);
        await publicClient.waitForTransactionReceipt({
          hash,
          confirmations: 2,
        });
      }
      return { hashes };
    },
    async waitForReceipt(hash) {
      const r = await publicClient.waitForTransactionReceipt({
        hash,
        confirmations: 2,
      });
      return {
        status: r.status === "success" ? "success" : "reverted",
        blockNumber: r.blockNumber,
      };
    },
  };
}
```

Then wire it into the engine:

```ts title="server/usdc-sender.ts"
import { createWhisk } from "@usewhisk/core";
import { createEvmAdapter } from "./adapter.js";

const adapter = createEvmAdapter(process.env.PRIVATE_KEY! as `0x${string}`);

const engine = createWhisk({
  chains: ["Base_Sepolia", "Ethereum_Sepolia"],
  mode: "testnet",
});

export async function sendUsdc(toAddress: string, amount: string) {
  const recipient = await engine.resolve(toAddress, "Ethereum_Sepolia");
  const quote = await engine.quote({
    recipient,
    amount,
    sourceChain: "Base_Sepolia",
    destinationChain: "Ethereum_Sepolia",
    adapter,
  });
  return engine.send({
    recipient,
    amount,
    quote,
    adapter,
    sourceChain: "Base_Sepolia",
    destinationChain: "Ethereum_Sepolia",
  });
}
```

## Beyond EVM

The same pattern works for Solana, Stellar, and Starknet. Build the
matching adapter (`SolanaAdapter`, `StellarAdapter`, `StarknetAdapter`)
using the ecosystem's node SDK — `@solana/web3.js`,
`@stellar/stellar-sdk`, `starknet` — and hand it to `engine.send`.
The engine picks the right adapter for the source chain
automatically.

Whisk's `packages/core/scripts/testnet/wallets.ts` in the repo shows a
production-shaped implementation of all four ecosystems side by
side; use it as a reference when you build your own.
