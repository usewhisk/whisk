Whisk is a React component you drop into a page so people can send
USDC. Once it's mounted, users can pay anyone with a wallet, on any
chain that Circle's CCTP V2 protocol reaches, with or without a
bridge in the middle. You don't have to think about wagmi configs,
CCTP step ordering, or Cairo `ByteArray` encoding; Whisk handles all
of that behind the component.

```tsx title="app/page.tsx"
import {
  WhiskProvider,
  WhiskSend,
  createWhiskConfig,
  evm,
  solana,
  stellar,
  starknet,
} from "@usewhisk/react";
import "@usewhisk/react/styles.css";

const config = createWhiskConfig({
  wallets: [
    evm({ projectId: process.env.WALLETCONNECT_PROJECT_ID! }),
    solana(),
    stellar(),
    starknet(),
  ],
  chains: [
    "Base_Sepolia",
    "Ethereum_Sepolia",
    "Solana_Devnet",
    "Stellar_Testnet",
    "Starknet_Sepolia",
  ],
});

export default function Page() {
  return (
    <WhiskProvider config={config}>
      <WhiskSend />
    </WhiskProvider>
  );
}
```

Save the file. Open the page. That's the entire integration. Connect
a wallet, type an address, type an amount, hit send. If source and
destination match, Whisk transfers directly; otherwise it routes
through CCTP V2 Fast Transfer.

## Three packages

`@usewhisk/react` ships the components, hooks, and providers.
`@usewhisk/core` ships the engine that drives them; pure TypeScript,
no React import. `@usewhisk/cctp` ships the CCTP V2 protocol layer
(chain registry, ABIs, Iris client, burn/mint builders across EVM,
Solana, Stellar, and Starknet). The React package re-exports the few
helpers most apps need, so you almost never have to import from core
directly.

## Four ecosystems, one widget

Whisk speaks every CCTP V2 destination Circle supports today:

- **EVM** — Ethereum, Base, Arbitrum, Optimism, Avalanche, Polygon,
  Linea, Unichain, World Chain
- **Solana** — via Wallet Standard (Phantom, Solflare, Backpack, …)
- **Stellar** — via Stellar Wallets Kit (Freighter, xBull, LOBSTR, …)
- **Starknet** — via get-starknet-core (Argent X, Braavos, …)

Cross-ecosystem bridges use Circle's Iris service to hand your burn
across chains and (where available) the Iris Forwarder to auto-mint
on the destination. Stellar and Starknet destinations mint manually
via the destination adapter.

## What it does that you don't have to

<Cards>
  <Card title="Recipient lookup" href="/docs/concepts/resolvers">
    Addresses, ENS names, and ENSIP-11 multichain coin types resolve against the
    destination chain. Bring your own resolvers; Lens, Farcaster, an internal
    email lookup, they slot into the same chain.
  </Card>
  <Card title="Quote and route" href="/docs/concepts/routing">
    Same-chain transfers go direct. Cross-chain transfers route through CCTP V2
    Fast Transfer; where the Forwarder covers the destination, the user signs
    once and the mint lands automatically.
  </Card>
  <Card title="State you can read" href="/docs/concepts/state-machine">
    Every transition fires through a discriminated union. Narrow on `state.kind`
    and the rest of the shape is fully typed. Good for analytics, custom UI, or
    a global app store.
  </Card>
  <Card title="A theme you can repaint" href="/docs/theming/overview">
    Every visible property routes through a CSS variable scoped to
    `[data-whisk]`. Override `--whisk-primary` once; the whole widget follows.
    Nothing leaks into the rest of your app.
  </Card>
</Cards>

## A note on status

Whisk is live on testnet across all four ecosystems today. Mainnet
is next. If you're building toward production, build against testnet
first. The API doesn't change between testnet and mainnet — only the
chain identifiers you put in `createWhiskConfig`.
